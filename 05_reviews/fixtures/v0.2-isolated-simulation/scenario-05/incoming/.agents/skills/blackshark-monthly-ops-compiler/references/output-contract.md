# 输出合同

## 本地输出目录与五件产物

从 `00_workspace/工作台地图.local.md` 读取正式产物目录；默认输出到 `03_my_workspace/02_outputs/YYYY-MM-门店名称/`。每次正式编译生成五件产物：

1. `本月运营方案.md`：保存符合固定七段式的 Markdown 正文。
2. `运营推进表.csv`：保存十字段、按固定顺序排列的动作记录，便于检查或手动导入。
3. `运营推进表结构.json`：保存推进表 schema，包括一张业务表、十字段、六状态和五视图。
4. `发布说明.md`：保存目标标题、建议位置、发布请求与执行状态，以及手动导入说明；不得包含凭证。
5. `验收结果.md`：分别记录本地结构验收、飞书发布和飞书回读结果，不得把三类状态合并。

生成职责和顺序见 `04_templates/本地产物包/README.md`。本地结构验收通过即可报告“本地交付完成”，但不等于飞书发布，更不等于飞书回读验证通过。

生成本地 `本月运营方案.md` 时，“配套推进表入口”必须写为 `[运营推进表.csv](./运营推进表.csv)`，并可同时链接 `[运营推进表结构.json](./运营推进表结构.json)`。飞书发布时只在外部副本中替换为实际 Base 地址，本地文件继续指向同目录产物。

正式五件产物不得保留模板变量。本地验收必须扫描 `{{` 和 `}}`；任一文件命中即失败，不得报告本地完成。`运营推进表结构.json` 中的 `{{目标门店}}`、动态执行线和其他 schema 模板值都必须解析为本月实际值。

## 文档头部

- 一句话月度重点。
- 最后拍板人。
- 运营推进人。
- 门店落地人。
- 配套推进表入口。

正文说明必须表达：文档负责方向与做法，推进表负责动作、承接人、日期、状态、验收和卡点。

## 七段式标题

一级标题严格依次为：

1. `1. 本月要做到什么`
2. `2. 谁负责什么`
3. `3. 本月排期`
4. `4. 各板块怎么落地`
5. `5. 本月先不做什么`
6. `6. 还有哪些要拍板`
7. `7. 这套文件怎么用`

不要增加第八段，也不要把推进表明细整段复制到文档正文。

## Base 结构

一个 Base 只保留一张名为“本月推进表”的业务表。

十个字段按此顺序创建：

1. 动作：文本，主字段。
2. 执行线：单选，选项跟随当月方案。
3. 状态：单选。
4. 归属：单选，至少包含“黑鲨”和目标门店。
5. 交付物/验收：文本。
6. 实际情况记录：文本。
7. 截止日期：日期。
8. 开始日期：日期。
9. 承接人：人员。
10. 阻塞/待确认：文本。

六个状态固定为：未开始、进行中、已完成、阻塞、待拍板、取消。

五个视图固定为：

1. 全部推进：按截止日期升序。
2. 本月排期：开始日期到截止日期的时间视图。
3. 按承接人：按承接人分组，组内按截止日期升序。
4. 待拍板与阻塞：只显示这两种状态。
5. 门店要做：只显示目标门店归属且未完成、未取消的动作。

## 动作最小合同

每条动作必须至少能回答：

- 做什么。
- 属于哪条执行线。
- 由黑鲨还是门店承担。
- 唯一主承接人是谁。
- 何时开始、何时完成。
- 用什么交付物或结果验收。
- 当前是什么状态。

常规月份默认控制在 20—30 条，但这只是复杂度边界，不是凑数目标。无法独立验收的细碎步骤应合并；真实经营需要超过范围时，在预览中说明原因后由操作者决定。

## 稳定记录键与 upsert

不增加第十一字段。同一门店、同一月份项目中，`动作` 主字段经首尾空白去除后必须唯一；规范化只去除首尾空白，内部标点和文字必须保留。空动作或重复动作均不符合动作合同。

飞书发布前回读现有 Base 记录，以规范化后的 `动作` 逐条匹配：0 条→创建，1 条→更新，>1 条→停止并列出冲突，不猜测应保留哪条。部分重试执行 upsert，只创建缺失记录、更新发生变化的记录，不重写未变化记录。

## 本地结构验收

- 五件文件存在、命名正确并位于地图指定的正式产物目录。
- Markdown 方案的文档头完整，七个一级标题顺序正确。
- CSV 第一行与十字段合同严格一致，每条记录满足动作最小合同。
- JSON schema 只有一张业务表，并符合十字段、六状态、五视图合同。
- 发布说明与验收结果不含凭证；本地、发布、回读状态分别记录。
- 正式五件产物不含 `{{` 或 `}}`；schema 的目标门店、动态执行线等均为本月实际值。
- `动作` 去除首尾空白后没有空值或重复；内部标点和文字未被改写。发现空动作或重复动作即本地验收失败。
- 所有状态字段只有一个值，发布请求、飞书发布和飞书回读状态组合合法；多值或非法组合导致本地验收失败。

只有以上检查通过，才把本地结构验收标记为“通过”并报告“本地交付完成”。飞书没有发布或没有回读通过时，保持对应状态，不得用本地完成替代外部发布结论。
