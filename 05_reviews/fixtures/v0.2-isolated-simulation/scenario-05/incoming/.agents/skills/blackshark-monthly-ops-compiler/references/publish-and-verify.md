# 可选发布与验收合同

飞书是可选出口，不是本地交付的完成前提。只有本地产物通过结构验收、操作者明确要求发布，并指定自己有权限的位置后，才进入外部写入。

## 身份、位置与权限边界

- 所有定位、查重、创建、更新和回读都使用操作者自己的身份和权限。
- 发布位置必须由操作者指定，并确认是自己已有权限的位置；工作台地图的默认发布位置为空，空值不代表授权。
- 没有发布能力或没有权限时，停止外部写入，保留完整本地产物，并在 `发布说明.md` 中提供手动导入说明。
- 不申请或扩大权限，不修改空间成员，不为了完成发布改变共享范围。

## 发布前预览与确认

1. 以只读方式定位操作者指定且本人有权限的飞书位置，并展示节点名称与路径。
2. 生成文档与 Base 的完整标题，建议统一使用“目标月份 + 门店 + 月度运营方案/运营推进表”。
3. 按完整标题搜索目标位置，列出现有同名或近似文档与 Base，先完成标题查重。
4. 展示发布前预览：方向、负责人、七段式正文、动作记录、十字段、六状态、五视图、缺口和目标位置。
5. 获得操作者对本次预览、目标位置和新建或更新方式的明确确认。

没有明确确认时保持只读，不创建、不更新、不移动任何外部内容。

## 发布顺序与复用

1. 复用已确认的同名 Base；没有匹配项时才创建一个 Base。重试时不重复创建同名 Base。
2. 在 Base 中创建或修正唯一一张“本月推进表”，确保十字段、六状态、五视图符合合同。
3. 不增加第十一字段；以 `动作` 主字段作为稳定记录键。规范化时首尾空白去除，内部标点和文字保持不变。同一门店、同一月份项目内，空动作或重复动作必须停止发布并报告。
4. 写入前回读现有 Base 记录，以规范化后的 `动作` 逐条匹配：0 条→创建，1 条→更新，>1 条→停止并列出冲突，不猜测正确记录。
5. 按预览对动作记录执行 upsert，并保存实际记录数。部分重试只创建缺失记录、更新发生变化的记录，不改写未变化记录。
6. 复用已确认的同名文档；没有匹配项时才创建文档。
7. 写入七段式正文，并只在外部副本中把“配套推进表入口”替换为实际 Base 地址；本地方案继续使用相对链接。
8. 将文档与 Base 放在操作者确认的位置，不自行改变空间成员或权限。

## 回读验收

发布后重新读取真实产物，不使用提交前草稿代替回读：

1. 回读文档标题、七个一级标题、三类负责人和配套推进表入口。
2. 回读 Base 标题和业务表数量，确认只包含本月需要的一张业务表。
3. 回读十个字段的名称、类型与顺序。
4. 回读状态选项和五个视图名称、筛选或分组规则。
5. 回读记录数，并抽查每条记录的动作、归属、承接人、日期、状态和验收。
6. 把文档入口、Base 入口、记录数、通过项、未通过项和验收时间写回 `验收结果.md`。

外部写入返回成功但回读失败时，只能报告“已尝试发布，尚未验证”。只有发布成功且回读全部通过，才报告“已发布并验证”。

## 三类状态分开记录

- 本地结构验收状态合法值：未检查、通过、未通过。
- 发布请求状态合法值：未请求、已请求。
- 飞书发布状态合法值：未请求、已尝试、已发布。
- 飞书回读状态合法值：未开始、通过、未验证。

每个状态字段只能写一个值。三类发布状态只允许以下组合：

1. 本地完成、未请求发布：`未请求 / 未请求 / 未开始`。
2. 已请求但没有权限：`已请求 / 已尝试 / 未开始`，并在未通过项写明“权限不足”。
3. 部分写入：`已请求 / 已尝试 / 未验证`。
4. 已写入但回读失败：`已请求 / 已发布 / 未验证`，只能报告“已尝试发布，尚未验证”。
5. 发布及回读完整通过：`已请求 / 已发布 / 通过`。

出现候选多值或任何非法组合时，发布验收失败，必须记录未通过项并停止成功结论。

本地结构验收通过只代表本地交付完成；不得据此把飞书发布状态或飞书回读状态写成成功。

## 部分失败与幂等

- Base 已成功、文档失败时，继续复用原 Base，只补文档，不创建第二份 Base。
- 文档已成功、记录不完整时，只修复缺失记录，不重复创建文档。
- 发布成功、回读失败时，下一次先查重和回读已有产物，再决定是否修复。
- 无法确认现有产物身份时停止写入，列出候选项请操作者决定。
- 部分失败时复用已经成功创建的产物，只补失败部分；不得通过重复新建来掩盖错误。
