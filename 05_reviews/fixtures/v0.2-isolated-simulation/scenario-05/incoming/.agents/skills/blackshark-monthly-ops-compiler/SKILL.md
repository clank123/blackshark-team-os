# 黑鲨月度经营编译器

## 目标与边界

把已确认的月度经营判断转成本地五件产物。方案固定为七段式；推进表固定为一个 Base 中的一张业务表、十个固定字段、六个状态和五个固定视图。飞书是可选出口，不是默认交付位置。

- 不替团队发明主方向、次方向或负责人。
- 不自动创建仪表盘。
- 不自动创建Workflow。
- 不自动创建多表经营控制台。
- 不为凑数量制造动作。

## 1. 读取地图并路由上下文

1. 起手读取 `00_workspace/工作台地图.local.md`。
2. 地图缺失，或地图记录的工作台、个人项目目录、正式产物目录路径失效时，立即停止并返回 `$blackshark-ops-router` 重新匹配；不得猜测、搜索后擅自替代或新建路径。
3. 从地图定位实际的个人项目目录和正式产物目录。未自定义时，项目目录使用 `03_my_workspace/01_projects/YYYY-MM-门店名称/`，正式输出目录使用 `03_my_workspace/02_outputs/YYYY-MM-门店名称/`。
4. 从用户输入识别目标门店和目标月份，读取 `01_shared_context/` 中的三份共享上下文及 `02_store_cards/00-七店索引.md`。
5. 只读取目标门店卡，不加载其他六店的详细卡。
6. 从目标项目的 `00_input/` 读取月度会议材料与明确补充，并读取 [输入合同](references/input-contract.md)。

## 2. 执行输入 Gate

检查以下必填项：目标门店、目标月份、原始月度会议材料、主方向、次方向状态，以及最后拍板人、运营推进人、门店落地人。

- 次方向可以是“无”，但不能处于未知状态。
- 任何必填项不足时，只输出缺口清单，不生成正式方案，也不生成本地五件产物。
- 当前状态缺少有效证据时明确标记“待门店确认”。
- 按“本月已确认会议事实 > 门店卡当前状态 > 门店卡长期基因 > 通用经营框架”的真值优先级处理冲突。
- 不猜测日期、数据、负责人或拍板结论。

## 3. 编译方案与推进表

1. 将材料分为已确认会议事实、已确认方向、待拍板、本月不做、现场观察或假设五类。
2. 允许本月已确认事实覆盖门店卡中过期的当前状态；不得静默覆盖长期基因。长期基因变化证据进入 `05_upstream_candidates/`。
3. 按 `04_templates/月度运营方案模板.md` 生成七段式正文。
4. 按 `04_templates/运营推进表模板/schema.json` 生成动作；每行满足动作最小合同。
5. 读取 [输出合同](references/output-contract.md)，校验标题、十个固定字段、六个状态、五个固定视图、动作数量边界以及缺口和待确认边界。

不增加第十一字段。同一门店、同一月份项目内，以 `动作` 主字段作为稳定记录键：匹配前首尾空白去除，内部标点和文字原样保留，规范化后必须唯一。空动作或重复动作都必须停止生成并返回修正清单。

## 4. 生成并验收本地五件产物

在地图定位的正式输出目录中生成：

1. `本月运营方案.md`
2. `运营推进表.csv`
3. `运营推进表结构.json`
4. `发布说明.md`
5. `验收结果.md`

草稿和中间检查分别留在目标项目的 `02_drafts/` 与 `03_verification/`；最终五件产物写入正式输出目录。使用 `04_templates/本地产物包/` 中的说明和模板，完成本地结构验收，并在 `验收结果.md` 中记录本地结果。

生成本地 `本月运营方案.md` 时，将“配套推进表入口”写为 `[运营推进表.csv](./运营推进表.csv)`，并可同时链接 `[运营推进表结构.json](./运营推进表结构.json)`。飞书发布时只在外部副本中替换为实际 Base 地址，不改写本地方案。

正式五件产物必须解析全部模板变量：扫描 `{{` 和 `}}`，任一文件仍有占位符即本地验收失败，不得报告本地完成。`运营推进表结构.json` 中的目标门店、动态执行线及其他 schema 模板值必须替换为本月实际值。发现空动作、规范化后的重复动作、状态字段多值或非法状态组合时，本地验收失败。

本地结构验收通过即可报告“本地交付完成”。这不代表已发布飞书，不得说已发布飞书。报告本地结果后询问操作者是否进入可选发布；没有明确发布请求时保持本地，不执行任何外部写入。

## 5. 可选发布前预览与确认

只有操作者明确要求发布时，才读取 [可选发布与验收合同](references/publish-and-verify.md)，并展示完整的发布前预览：

- 一句话月度重点和三类负责人。
- 七段式正文。
- 按执行线分组的动作记录。
- 十个固定字段、六个状态、五个固定视图。
- 缺口、待拍板和待门店确认事项。
- 操作者指定且本人有权限的目标位置、文档完整标题和 Base 完整标题。

预览阶段保持只读。只有获得操作者明确确认本次预览、目标位置及新建或更新方式后，才进入发布。

## 6. 可选发布与回读验收

1. 按完整标题搜索已有文档和 Base。
2. 有匹配产物时优先更新或复用；不重复创建同名 Base。
3. 写入前回读现有 Base 记录，并按首尾空白去除、内部标点和文字不变的 `动作` 键逐条匹配：0 条→创建，1 条→更新，>1 条→停止并列出冲突，不猜测正确记录。
4. 先创建或复用 Base 与一张业务表，再创建或更新文档。部分重试执行 upsert，只处理缺失或发生变化的记录。
5. 将 Base 的实际入口只写入外部文档副本头部“配套推进表入口”。
6. 回读文档，检查完整标题、七段式内容和配套推进表入口。
7. 回读 Base，检查一张业务表、十字段、六状态、五视图与记录。
8. 将飞书发布状态与回读状态写入 `验收结果.md`，不得覆盖本地结构验收状态。

只有发布成功且全部回读通过，才能报告“已发布并验证”。回读失败或只能确认部分结果时，必须指出未验证项，不得声称交付已验证。

## 7. 失败与幂等

- 创建前按完整标题查重，重试时复用已创建的产物。
- Base 已成功、文档失败时，继续复用原 Base，不新建第二份。
- 文档已成功、记录不完整时，只修复缺失记录，不重复建文档。
- 无法确认现有产物身份时停止写入，列出候选项请操作者决定。
- 所有未确认事项保持“待拍板”或“待门店确认”，不得悄悄改成已决定。
