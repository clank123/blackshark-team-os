# 首次启用

此 Skill 不会在安装后后台弹出。成员第一次发起黑鲨任务，或发送“启用黑鲨门店运营工作台”时，才触发首次启用。

按以下八步执行，并保持“检测 → 推荐 → 询问 → 配置”的顺序：

1. 检查 Skill、完整知识包与 `workspace-manifest.json` 是否存在且可读取。
2. 识别当前及可见上级目录的 Obsidian 标志，列出可能承载工作台的位置。
3. 检查候选位置，避免重复创建工作台。
4. 展示候选位置，并推荐“嵌入已有知识库”或“独立工作区”。
5. 请成员确认目标位置：多个知识库候选时让成员选择；仅有一个候选时仍须确认；没有候选时推荐独立工作区或由成员指定位置。未获得确认不代为决定。
6. 确定补齐来源：manifest 存在时优先使用 manifest 声明的公共仓库来源；只有 Router Skill 或 manifest 缺失时使用上述内置公开 fallback `https://github.com/clank123/blackshark-team-os`。先展示来源、目标、将创建或覆盖的内容；下载或复制前必须取得成员对这三项的明确确认。
7. 得到确认后才创建个人目录，并从 `00_workspace/工作台地图模板.md` 生成 `工作台地图.local.md`。
8. 运行五项验收，展示结果与仍待成员确认的信息。

确认前不执行任何下载、复制、移动或创建；确认后才可进行补齐完整知识包、复制文件、移动内容或创建外部目录。

## Router-only 补齐与身份校验

公开 fallback 固定为 `https://github.com/clank123/blackshark-team-os`，仅用于本地 manifest 不存在或不可读取的 Router-only 场景。manifest 存在时优先使用 manifest 声明的公共仓库来源；manifest 缺失时使用上述内置公开 fallback，不得反过来要求一个并不存在的 manifest 提供来源。

成员确认来源、目标、将创建或覆盖的内容后，在最终目标的同级目录建立本次唯一暂存目录。所有下载或复制只进入这个暂存目录，不直接写最终目标，也不复用其他运行留下的暂存目录。

下载或复制完成后，读取暂存目录中的 `workspace-manifest.json`，并在任何最终写入前严格验证：

- `workspace` 必须等于 `blackshark-team-os`；
- `schema_version` 必须等于 `2`；
- `release` 必须等于 `v0.2`；
- manifest 声明的工作台关键目录和实际载荷必须存在。

身份、schema、release 或关键载荷任一不匹配时立即停止，不得覆盖最终目标，最终目标保持原样。默认只清理本次唯一暂存目录；如果成员明确要求保留失败样本用于检查，可保留该暂存目录并清楚标记“校验失败、不得启用”，但不得把它重命名或移动为最终目标。清理或保留都只作用于本次唯一暂存目录，不处理来源、既有目标或其他目录。

校验全部通过后仍要检查最终目标是否已经存在或含同名内容；有冲突时停止并展示差异，不自动合并或覆盖。只有目标无冲突，才把已校验的暂存内容在同级原子切换到最终目标，然后继续生成本地地图与个人目录。

五项验收：

1. 能定位工作台根。
2. 能读取共享上下文与七店索引。
3. 个人目录已按地图可用。
4. 两层 Skill 都可定位：Router 与月度编译器。
5. 飞书默认目标为空，直到成员明确指定。

未经确认，不移动现有仓库、不创建外部目录、不覆盖同名文件。此流程不包含工具安装教程或发布操作说明。

## v0.1 兼容迁移

完成上述八步后，如发现 `03_projects/` 或旧复盘目录 `05_reviews/月度复盘候选/` 有真实内容，Router 必须先展示迁移计划，而不是直接处理。项目迁移只排除根脚手架文件 `03_projects/README.md`，复盘迁移只排除根脚手架文件 `05_reviews/月度复盘候选/README.md`；任何项目内部或嵌套 `README.md` 一律视为用户真实内容，纳入清单、复制和验收。未经确认不复制、移动、重命名、删除；确认后默认复制，并保留源文件。旧副本默认不删除；未经迁移后第二次明确确认不删除。

### 预检迁移清单

预检逐文件生成迁移清单，列出来源、目标、源相对路径、映射后目标相对路径、文件数量、字节数、SHA-256、目录映射、映射结果和同名冲突。旧项目目标为 `03_my_workspace/01_projects/YYYY-MM-门店名称/`，且五条映射必须精确：`00-input/` → `00_input/`、`01-context/` → `01_context/`、`02-drafts/` → `02_drafts/`、`03-feishu-payload/` → `02_drafts/legacy-feishu-payload/`、`04-verification/` → `03_verification/`。未知内容放入目标项目 `legacy-v0.1-unmapped/`，未知内容保持相对结构，不丢弃。

预检先检测两个源映射到同一最终相对文件路径的迁移内碰撞，也检测既有目标同名/同路径；任何碰撞先停止，展示差异让用户决定，不合并猜测。父子目录本身不视为同一路径重复，真正碰撞按最终相对文件路径判断。同名目标或目标已有内容时停止自动迁移，展示差异让用户决定。必须明确预检 `02-drafts/legacy-feishu-payload` 与 `03-feishu-payload` 等可能映射到同一路径的碰撞。旧复盘由成员逐项选择写入个人 `03_my_workspace/03_reviews/` 或团队候选 `05_upstream_candidates/`；归属不确定时必须让用户选择，不猜。

### 复制、验收、收据与清理

确认后，在最终目标的同级目录建立本次唯一暂存目录，先全部复制到暂存，不直接写最终目标。用相对路径+字节数+SHA-256 逐文件核验载荷；任一失败只清理本次唯一暂存目录，源文件与既有最终目标保持原样。全部载荷核验后，先生成并核验迁移收据.md（在本次唯一暂存目录内）。收据记录并引用载荷文件清单的 SHA-256，以及源清单摘要、目标、映射、文件数、哈希验收和完成时间；载荷哈希明确排除收据自身，避免自引用。收据生成或核验失败仍只清理本次唯一暂存目录，源文件与既有最终目标保持原样。仅当载荷与收据均核验成功，再将包含收据的暂存目录一次性同级重命名为最终目标。

最终目标验收时确认迁移收据.md 存在，并重新计算除收据外载荷清单哈希，确认与收据一致。二次运行先读最终目标内收据：源未变+目标哈希一致→跳过，报告已完成。源或目标变化、收据不一致时停止并展示差异，不重复复制/合并。验收新位置后，再次询问是否移动/清理旧副本；清理前重新核对收据与目标哈希，失败不清理源。迁移失败也保持旧内容原样，不自动删除。
