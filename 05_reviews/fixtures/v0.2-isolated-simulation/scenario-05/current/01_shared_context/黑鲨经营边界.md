# 黑鲨经营边界

> 隔离模拟的本地基线修改：本行必须在更新冲突时保留。

适用范围：门店月度经营方案、运营推进、内容与渠道动作、平台承接和复盘。

# 我们负责什么

- 把已经确认的门店经营方向翻译成可执行动作、负责人、日期、交付物和验收标准。
- 判断每个动作主要推动哪一段经营链路：看见、看懂、购买、到店、现场经营、复购或口碑复用。
- 让内容、平台、活动、达人、私域和现场动作都能对应真实经营目的，不把“做了很多事”当成经营结果。
- 在发布前指出材料缺口、责任不清、日期冲突、未拍板事项和无法采集的指标。
- 用文档讲清方向和做法，用推进表记录动作、状态、卡点和实际情况。
- 保留执行过程的变化证据，让月底能解释为什么继续、插单、降配、延期、取消或重排。

# 我们不替门店决定什么

- 不替胡子决定产品、实体经营和门店现场的最终方向。
- 不单方面决定价格和预算。
- 不把会议中的讨论、建议或匿名强表述升级成正式拍板。
- 不虚构销量、预算、用户行为、实付、复购、毛利、负责人或资源承诺。
- 不因旧门店档案写过某个状态，就忽略本月会议中的最新事实。
- 不把曝光、报名、领取、热闹或一次成功直接等同于利润和可复制方法。

在现有协作边界中：产品与实体运营由胡子主导；价格和预算共同确认；内容和渠道由黑鲨主责；门店现场共同判断、胡子高权重；数据获取共同负责。

# 利润与证据

门店利润可先用以下结构理解：

```text
利润 = 到店订单数 × 客单价 × 毛利率 × 复购频次
     - 获客成本 - 优惠成本 - 人工成本 - 物料成本 - 平台成本
```

每个动作至少回答四个问题：

1. 它影响利润公式中的哪一项？
2. 它希望用户发生什么可观察行为？
3. 做完留下什么交付物或现场证据？
4. 到什么时间，根据什么信号决定继续、加码、降配或停止？

证据优先使用收银、平台后台、核销、现场记录、评价、用户反馈、内容表现和明确会议结论。没有采集路径的“品牌指数”“传播转化率”等伪精确指标不能作为正式验收。

# 团队交付语言

- 写“谁在什么时间完成什么”，不写空泛口号。
- 写“怎样算完成”，不只写“推进、加强、持续优化”。
- 未确认事项统一放入“待拍板”，并写清拍板人和最晚确认时间。
- 门店可读内容使用直接动作语言，不暴露不必要的内部术语。
