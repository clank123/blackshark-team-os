# 月度复盘候选区（v0.1 兼容目录）

这是 v0.1 的兼容目录。旧副本默认不删除；未经迁移后第二次明确确认不删除，仍可作为历史候选查阅；新的个人复盘写入 `03_my_workspace/03_reviews/`，希望团队吸收的候选写入 `05_upstream_candidates/`。

这里原本收集可能值得复用的经验，不直接更新共享真值。每条候选至少写清：来自哪家店、哪个月份、原判断、实际发生、证据、建议保留或修正的内容。候选必须由知识库负责人确认后，才能更新内部知识母仓和下一版团队包。未确认前，不得用候选经验覆盖其他门店或后续月份。

## 迁移合同

Router 在迁移旧候选前，只排除根脚手架文件 `05_reviews/月度复盘候选/README.md`；嵌套 `README.md` 一律视为用户真实内容，纳入清单、复制和验收。逐项展示来源/目标/数量/字节数/SHA-256 清单、映射和同名冲突，再等待成员确认。不确定某项属于个人复盘还是团队候选时，归属不确定时必须让用户选择，不猜。

确认后默认复制并保留源文件：先在最终目标同级建立本次唯一暂存目录，只复制到暂存，再用相对路径、字节数和 SHA-256 核验载荷。任何迁移内碰撞或既有目标同名/同路径都停止；任一失败只清理本次暂存，源与既有目标不变。全部载荷核验后，先生成并核验迁移收据.md（在本次唯一暂存目录内）；收据记录并引用载荷文件清单 SHA-256、来源、目标、数量、映射、哈希验收和完成时间，且载荷哈希明确排除收据自身，避免自引用。收据生成或核验失败仍只清理本次暂存，源与既有目标不变。仅收据和载荷都通过核验，才将包含收据的暂存目录一次性同级重命名为最终目标。

最终目标验收时确认迁移收据.md 存在，并重新计算除收据外载荷清单哈希与收据一致。二次运行先读最终目标内收据：源未变+目标哈希一致→跳过；有差异或收据不一致时停止并展示差异，不重复复制/合并。新位置验收并重新核对收据与目标哈希后，Router 另问是否清理旧副本；核对失败或未经第二次明确确认，不清理源。
