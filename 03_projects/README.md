# 月度项目区（v0.1 兼容目录）

这是 v0.1 的兼容目录。旧副本默认不删除；未经迁移后第二次明确确认不删除。它保留原有结构，供旧项目继续查阅。新项目请写入 `03_my_workspace/01_projects/YYYY-MM-门店名称/`，并使用 v0.2 结构：

```text
YYYY-MM-门店名称/
├── 00_input/
├── 01_context/
├── 02_drafts/
└── 03_verification/
```

## 原五子目录结构（继续可读）

每家店每个月曾建立一个本地目录：

```text
YYYY-MM-门店名称/
├── 00-input/
├── 01-context/
├── 02-drafts/
├── 03-feishu-payload/
└── 04-verification/
```

- `00-input/`：月度会议材料、已确认方向、负责人和限制。
- `01-context/`：本次使用的共享上下文和目标门店卡副本。
- `02-drafts/`：七段式文档和动作清单预览。
- `03-feishu-payload/`：本次确认后的飞书发布载荷，不保存凭证。
- `04-verification/`：发布后的文档、Base、字段、视图和记录验收结果。

除本说明外，该目录下的实际项目默认只保留在成员自己的电脑中。

## 迁移合同

这是文档与 Skill 的执行合同，不是自动迁移脚本。Router 盘点时只排除根脚手架文件 `03_projects/README.md`；任何项目内部或嵌套 `README.md` 一律视为用户真实内容，纳入清单、复制和验收。迁移前先展示计划并等待确认，旧副本默认不删除；未经迁移后第二次明确确认不删除。

### 预检与映射

预检生成逐文件迁移清单，逐项列出项目名、源相对路径、映射后目标相对路径、字节数、SHA-256 和映射结果。先检测两个源映射到同一最终相对文件路径的迁移内碰撞，也检测既有目标同名/同路径；任何碰撞先停止，展示差异让用户决定，不合并猜测。父子目录本身不视为同一路径重复，真正碰撞按最终相对文件路径判断。特别预检 `02-drafts/legacy-feishu-payload` 与 `03-feishu-payload` 等可能映射到同一路径的碰撞。

目录映射固定如下：

- `00-input/` → `00_input/`
- `01-context/` → `01_context/`
- `02-drafts/` → `02_drafts/`
- `03-feishu-payload/` → `02_drafts/legacy-feishu-payload/`
- `04-verification/` → `03_verification/`

未知内容放入目标项目的 `legacy-v0.1-unmapped/`，未知内容保持相对结构，不丢弃；嵌套 README 同样纳入上述规则。

### 复制、验收与恢复

确认后默认复制并保留源文件。在最终目标的同级目录建立本次唯一暂存目录，先全部复制到暂存，不直接写最终目标。再以相对路径+字节数+SHA-256 逐文件核验暂存中的载荷内容；任一失败只清理本次唯一暂存目录，源文件与既有最终目标保持原样。

全部载荷核验后，先生成并核验迁移收据.md（在本次唯一暂存目录内）。收据记录并引用载荷文件清单的 SHA-256，以及源清单摘要、目标、映射、文件数、哈希验收和完成时间；载荷哈希明确排除收据自身，避免自引用。收据生成或核验失败仍只清理本次唯一暂存目录，源文件与既有最终目标保持原样。仅当载荷与收据均核验成功，再将包含收据的暂存目录一次性同级重命名为最终目标。

最终目标验收时确认迁移收据.md 存在，并重新计算除收据外载荷清单哈希，确认与收据一致。验收新位置后，才再次询问是否移动/清理旧副本；在清理前重新核对收据与目标哈希，失败不清理源。二次运行先读最终目标内收据：源未变+目标哈希一致→跳过，并报告已完成。源或目标变化、收据不一致时停止并展示差异，不重复复制/合并。
