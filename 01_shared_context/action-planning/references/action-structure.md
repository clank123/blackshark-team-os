# Action structure｜把行动想清楚

## 共同拆解时，先找到卡住下一步的判断

用户说“做设计”时，未必缺设计步骤，可能还没决定设计要帮助顾客看懂什么。按当前缺口追问，不把下列问题逐项发成问卷：

| 看到的缺口 | 可以怎样问 | 答案应该改变什么 |
| --- | --- | --- |
| 只有产物名，没有用途 | 这张图放在哪里，顾客看完需要知道什么或做什么？ | 信息重点、规格、完成依据；不必重开已定策略 |
| 一条任务包含尚未完成的判断 | 做出这份稿前，哪些内容必须先定？依据现在在谁手里？ | 先收资料、作判断，再开始制作的依赖 |
| 写了“对接”，但交接不明 | 对方要拿到什么才能开始？回来什么才足够让下一岗接手？ | 输入、责任边界、交接物 |
| 任务看似完成，实际用不了 | 从收到成品到真正使用，中间还经过谁、需要什么条件？ | 配置、现场执行或必要的路径核验 |
| 只算制作时间 | 还要花多少次沟通、审改、回收或跟进？等待的是什么？ | 一次性、持续性与外部等待的区分 |

先利用现有资料自行补全能推定的部分，并标为建议。必须由用户或业务方决定的条件，不能靠 AI 编造；将其交给有判断责任的岗位，而不是把每个问题都推回用户本人。说明本轮已定、仍开放及直接影响的下一步即可。

## 一条任务什么时候足够细

让实际承接者可以回答：为什么需要它？拿什么开始？要处理哪个关键问题？交出什么、给谁？何时或什么条件下完成？不要求每个答案都各占一列。

- **值得独立拆出：** 要等待另一人给资料；有独立业务决定；产物要交给下一岗；需要分别排期或验收；不同责任混在一起会掩盖工作量。
- **保留为同一任务的子步骤：** 同一人连续完成的收集、整理、标注，可一起交出一个可用成果；逐条不需要独立调度。
- **可以停止：** 开始条件、关键判断与交接已清楚，余下属于承接者已具备的专业方法。不要把点击按钮、常规文件操作、每个镜头都变成管理任务。
- **还不够：** 换成“负责推进、完成相关准备、做好设计”后仍不知道明天先做什么；或写了时间与人名，但仍靠执行者猜产品、规则或交付用途。

删去一项，若既不影响目标、必要依赖，也不减少需要解决的不确定性，就检查它是否只是装饰性的工作。必要性可以是假设，但要说出要验证什么，不能把预期销售效果写成已证实因果。

## 示例：同样是“准备活动报名页”

以下是虚构示例，不是任何真实项目的事实或固定任务数。

场景：已决定举办一场工作坊；需要让访客选对场次并成功报名。场次资料分散、旧照片未核对；设计、运营与现场接待分别负责。只写“运营协调设计上线报名页，周五完成”，仍把输入、业务判断和交接藏在一句话里。

可按实际责任拆成：

1. **核实可报名场次。** 活动负责人据讲师与场地确认，整理场次、名额、费用及适用人群，给内容和运营共用，避免展示不可兑现的选择；未定项保留决定人和需要决定的时间。
2. **整理页面信息与素材要求。** 内容负责人据已核实的场次，确定访客先看什么、怎样选场次；给设计页面结构、各图表达及风格参考。参考收集属于真实工时，不默认设计自行猜方向。
3. **核对现有素材并补缺。** 素材提供方交照片；内容负责人对应实际场次和使用位置，标出可用与缺口。可以先收照片，但最终匹配依赖场次表；只有确实缺的素材才补拍。
4. **设计并移交运营。** 设计按结构、素材与实际页面规格完成稿件，校对后给运营可用文件；运营据最终内容配置。两岗需要独立排期时拆开管理，简单协作也可在同一工作块下保留两次交接。
5. **按需要试走报名与接待。** 若是新报名路径，运营与接待核对场次选择、确认通知及名单交接，修正问题后再开放推广。只是修正一个已确认的错别字，则局部回读即可，不重做整条路径测试。

这里拆出的核心是“先判断什么，才能让谁开始”，不是五步这个数字。报名后是否还需要名单更新、咨询接待与结案，取决于委托范围；确实需要的持续工作不能因页面上线而消失。

反例：已定稿的海报只需设计将活动日期改为已确认的新日期，交运营替换。说明正确日期、使用位置和替换后的核对就够；无需重做受众研究、安排会议或新增项目。专业摄影师收到用途、必需素材、边界、交期后，可以自行选择机位、器材与剪辑方式，除非用户明确委托详细脚本。

## Dependency pass

Check five kinds of dependency:

1. Information: a definition, asset, inventory state, or source must exist.
2. Sequence: one action must finish before another can start.
3. Capacity: the same person, store, budget, or channel is claimed twice.
4. Authority: a genuinely new commitment crosses the current decision boundary.
5. Evidence: the action can run, but its effect cannot be judged until a source and window exist.

The priority view may group or rank actions for attention. Keep a traceable complete list underneath it so grouping cannot hide required work.

## 排期与工作量

- 从真正要发生的交付节点倒推。资料齐备→决定→制作→交接→使用，不因把日期填满而忽略依赖；可先行的部分继续并行。
- “下周五需要可用”是需求日期，不是外部办理已经承诺。未知等待留下一反馈节点和受影响窗口，不能虚构两天一定办完。
- 区分已定日期、AI 倒排建议、条件排期与事件相对时间。人员未定先写岗位，不把多个岗位当作已经存在的多个人。
- 工时只在用户需要时估。说明对应数量、修改轮次、信息成熟度等假设；估不准时给区间或先计实测，不报假精确数字。
- 一次准备、每个对象的执行、每次检查、日常跟进分别计量。例如“统一内容要求”与“逐位合作方跟稿”不能既计入固定统筹，又按对象重复计。
- 一人兼两岗时检查真实日历和主动工时。等待两天不等于工作十六小时；两项各半天也不意味着可在同一个上午完成。按用户提供的休息安排调整。

## 输出前作一次实际交接检查

选择最容易卡住的一条依赖，尝试说明：上一岗给出什么，下一岗凭什么开始，谁作尚未作出的判断。如果仍只能说“到时候沟通”，把该缺口补成具体的准备或决定动作。它影响哪个节点就标哪个节点，不冻结整个项目。

同时检查是否重复追问了已定事项、是否替专业同事作了未委托的细节、是否新增了无必要目的的任务。任务数、字段数、填满程度都不是质量指标。清单可以按工作块展示，详细推理留在需要它的位置。

## Handoff choice

- Direct note: one owner, low risk, reversible, no independent gate.
- Coordinated handoff: multiple owners or dependencies, but one shared decision boundary.
- Project package: material resource commitment, independent gates, sustained coordination, or several linked result decisions.

Use `blackshark-project-handoff` when the work has to cross from planning into coordinated execution.
