# 团队如何一起使用

这份包归黑鲨（BlackShark）维护。它包含通用方法与本地记录工具，没有任何真实门店数据或私人工作区依赖。本方法随 blackshark-brand-store-skills v0.3.0 按现有 Apache License 2.0 发布，许可见 LICENSE；当前门店资料与经营结果不进入公共包。

## 保留已有入口

单独使用时，将本目录作为 `blackshark-monthly-planning` Skill 安装到所用AI工具的技能目录，随后可直接说“给这家店做下月规划”。不同客户端的发现/重载方式以其实际能力为准，安装文件不代表所有团队成员已可调用。

已有黑鲨团队工作台时，保留 `blackshark-ops-router` 与 `blackshark-monthly-ops-compiler` 两个入口，不要求运营再记一个入口：

1. 将本方法目录放到 `01_shared_context/monthly-planning/`。共用质量文件为 `references/workflow-quality.md`，营销选择为按需读取的 `references/marketing-choice.md`；维护源是原版方法包，策略核心也分发同一营销选择文件。分发保持逐字一致，不在副本各写一套。团队版固定引用公开版本和文件指纹；本地候选与已发布版本分开登记。
2. 在两入口的月度规划分支读该目录 `SKILL.md`，先接回本店资料、人群库和上月结果，再沿原月度编译器生成原方案与推进表。入口已读过的方法不用再跑一遍。
3. 在已有“收到门店事实/结果”分支调用该目录 `references/feedback.md`，把受影响主张接回原店记录。单项交付验收不展开整月。
4. 每店私有索引保存当前库、修订记录、当期项目、来源覆盖和权限维护角色。业务数据沿个人或授权共享目录，不能放在会被软件升级替换的共享方法目录。
5. 保留旧模板、任务编号、已定方向、成员本地记录与原更新器。升级时先比文件基准；成员改过的入口需合并，不能直接覆盖。

同一店只能有一个约定的当前库；先决定谁保存、谁可读、谁可改。成员个人副本是提案或缓存，不自动成为公共版本。跨店复用是带原条件的候选；不能复制份额和效果。这个包不提供跨设备同步或平台登录能力。

## 建议的第一轮运行

用一家已授权门店，沿现有数据途径完成一次更新→建议→自然执行反馈→卡片修订。负责人只决定原权限没有覆盖的投入与方向，店长核现场，运营接职责内细节。人工导出的数据也可开始，不必等所有平台接口打通。

先看能否减少搬资料和返工、是否发现有依据的遗漏，再接经营结果。不以报告更长、人物更鲜活、与老板意见一致来验收。

## 再接定期更新

每周补资料、规划前集中核对、重大变化及时重看是起始建议。已有日检取得的资料直接复用；先核各来源实际能自动读取哪些、哪些需要登录或人工导出，再配置调度。没有重要变化保持安静；登录失败、关键数据缺口和需要决定的变化才通知相应人。

团队部署验收分别核：方法能被调用、每店资料权限正确、更新有覆盖与失败回执、结果修订可回读、多人改动不互相覆盖、成员实际能用。以上都不等于已证明经营收益。
