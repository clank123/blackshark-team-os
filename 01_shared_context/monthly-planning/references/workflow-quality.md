# 月规划的目的、产出与结果

共用方法版本：monthly-quality-2026-11-08.1。维护源为 blackshark-monthly-planning 的本文件；原版和团队版分发同一内容。它约束判断关系，不固定门店做法、项目数、预算、时间、样本量或增长比例。月中更新只处理受影响部分，单项交付不展开整月。

## 目的怎样形成

比较顾客方向、价值主张或相应资源时，按[营销选择](marketing-choice.md)核需要/角色/关系阶段、相对价值和整次消费的适配，区分引发选择与帮助兑现的利益，再决定本月最该改变哪一步。该判断映射现有方案，不另建必填表。

先接回当前问题、机会、品牌选择或需要保护的经营条件。沿负责文档及有效变更核当前入口；旧表读取成功不等于当前覆盖，较新文件日期也不自动胜过有效决定。区分可回查事实、本人/团队报告、已定选择、AI解释与未知。同源摘要不增加证据；模拟顾客不能证明需求。

把观察、原因解释、手段分开：指标下降是线索，“因信息不清”是假设，“改页面”是手段。不能从活动名或现有资源直接推出经营目的。对顾客方向连清：

- 人在什么处境下想完成什么，还会选什么；哪些真实选择或表达支持它。
- 为什么可能选本店、什么会让他放弃；不能从套餐规格推人数、从年龄职业推需求。
- 当前能否触达并兑现，是否伤害其他顾客、正常经营或并行工作。
- 相比其他现实用途，这笔钱和时间为什么值得现在投入。

维护或履约工作可直接解释保护的条件，不硬编增长故事。品牌价值可以是经营者的选择，但相关效果假设仍待检验。人群描述应改变具体选择；需求模型不是已经拥有的人群资产，后者要逐步有反复选择、推荐与价值的证据。

比较可能改变取舍的替代方向，包括延续或不追加投入，给明确推荐与代价；不要求固定数量、加权评分或全部都做。经济贡献、持续经营基础、减少关键未知可分别构成理由，但不能用“长期资产”抵消明确损失。计入等待和错过时机的代价，不能永久停在“补基础”。

预算分总额、已支出、已承诺、剩余可支配。其他账户承担的费用仍须在对应经营判断中考虑。收入/核销不等于新增贡献：看退款、平台费用、耗用、替代原消费、挤出的经营及人手；已扣费用不重复扣。缺基线或成本时不编增长、利润或ROI。

目的表达到可取舍：为改善/保护什么，在什么期间、场合，让哪种顾客选择或经营条件变化；本期走多远、受什么资源约束，依据与改判条件是什么。保留经营意图；若本期只能完成准备或学习，明确其层次，不把产物数量换名为经营达成。

## 证据不足怎样推进

| 情况 | 本轮推进与限制 |
| --- | --- |
| 未知不影响已定、能兑现的工作 | 继续，保留相关未知；不重开其他已定方向 |
| 方向有理由，需求或效果仍弱 | 投入上限、兑现条件、观察方式明确时，可有边界地尝试；写清结果将改变哪笔投入或哪项选择 |
| 成本、规则、供给或现场缺口影响承诺 | 核关键项，独立准备并行；限制依赖它的承诺或新增投入 |
| 有可能破坏核心承诺的反证 | 核是否仍适用，调整范围或做法；不能用文案藏问题，也不以孤例否定所有需求 |
| 记录空白、执行未知或结果未成熟 | 分别核实、等待对应窗口；不判非执行或需求失败，跨月继续接回 |

关键缺口只交清：缺什么 → 改变哪个选择 → 最省力的取得方式及能提供事实的岗位 → 现在仍能做什么 → 哪个决定时点必须处理。由AI先用现有资料整理，不加一张运营必填表，也不把现场事实全部交老板确认。

已有足够依据作本阶段选择、更多信息不再改变选择，或取得/等待代价超过价值时，停止补取。关键问题补不到则缩小、调整或暂缓相应投入；“待补”不能成为无限花钱的许可。授权内可逆工作直接承接，新增承诺超出现有权限才交具体选项给有权限的人。

## 关键产出怎样接到验收

连成：**经营目的 → 本期希望改变什么 → 做法及关键假设 → 当前关键产出 → 实际使用 → 顾客/经营结果 → 下一次选择。** 同一产出可支持多个目的，共用一次准备，不重复计成本和收益。

沿原方案和任务编号，每项关键产出说明实际对象、用途和接收者、必须准确完整的内容与限制、开始/交接依赖及岗位/期限或条件、核哪个实际版本及凭证、使用后看什么。不要只写“策划方案、完成拍摄、做好推广”。粒度按委托与接收职责：委托AI做完整方案就补完关键业务做法；委托专业岗位设计则交清输入、约束和验收，保留其专业自主。

完整稿交付前选最容易断的一条真实链走通资料→决定→制作→交接→使用，检查谁拿什么开始、共享资源是否冲突、是否缺持续工作；发现问题修正文和对应任务，不只在末尾列建议。保留有效并行工作，不能为突出主线丢掉已有安排。

| 判断层次 | 查看与可下结论 |
| --- | --- |
| 规划质量 | 依据、取舍、边界、做法与交接：可讨论/相应部分可交接，不保证成功 |
| 产出交付 | 实际版本是否符合约定、准确且接收岗能用：交付合格/需修，不等于已上线 |
| 准备与执行 | 产品、规则、人员、现场是否一致；实际使用时间及偏差：准备好和实际发生分别留证 |
| 顾客结果 | 对应情境下真实询问、选择、到店、体验、复来：只支持已观察行为，不用发布/播放代替 |
| 经营结果 | 同口径消费、成本、贡献、替代和其他影响：支持保持/追加或调整到何种范围，归因不足仍注明 |

内部维护核相应条件即可。不强制新增状态、表或审批；结果写回现有方案和实际记录。前层可先完成，后层继续观察；未成熟效果不抹掉已交付事实，购买增加也不能自动判整体成功。注明结论来自程序、AI内容审阅、实际材料、岗位确认或尚未验证，不能互相冒充。

## 结果回来怎样改判

先取回当时的目的、假设、动作/商品版本、投入与观察约定。按相关性核来源/口径、实际执行、触达、兑现、结果窗口与同期变化，再说明支持或挑战哪一条判断；不能用今天改过的方案解释过去结果。

若证据改变选择理由、提供条件或投入价值，用[营销选择的改判要求](marketing-choice.md#改判要进入原来的交付)把目的/主次/投入的变化落到原产出、接收与验收；不能只更新叙述，保留原行动不变。没有变化也应说明依据。

- 未执行不反证需求；空白记录连执行也未知。修承接，不造效果。
- 触达或兑现不足，先限制结果解释；反复做不到或代价过高也足以停止该做法，不能无限以执行为由重试。
- 看懂并有机会使用仍因价格/场景/条件拒绝，修相应选择条件或优先级，不默认继续加曝光。
- 有使用和满意但贡献不足，调整权益、成本或获客方式，必要时停止追加；不能用人群资产自动弥补亏损。
- 行为与贡献改善但有同期变化，保留观察到的改善，不能独归因某内容或卡片。扩量仍受容量、成本、机会成本约束。
- 覆盖不足、数据冲突、窗口未满，保持该项未知并说明下一次判断点；明显损失或即时错误无需等月末才处理。

沿原项目简记：原判断/版本 → 新结果与限制 → 继续、调整、收缩、停止或暂不能判断的建议 → 哪些动作与投入改变、哪些保持 → 未解项与下一决定点。结果判断与实际决定分开，状态映射原载体。已回答的旧问题更新，未回答保留；迟到核销/复来跨月接续。方法能否复用另看多次真实使用、适用条件、反例与人的返工/维护负担，不能用一次通过代替。

## 交付底线

编造事实/决定/负责人承诺、丢失关键已定内容、隐藏影响取舍的反证、核心承诺不能兑现却标可执行，退回相应部分修改；不由总分或排版抵消。合理标明未知并给出有限建议，不自动判整份不合格。其他有效部分继续。

结构脚本只能查关系和格式；AI内容审阅检查上述关系；门店确认兑现；实际结果检验判断。两版在同输入下可以有不同表达与建议重点，但关键事实、条件和交接不能漂移；实质取舍不同须说出依据。任何单店的具体数字、套餐、时段、人数与做法均为案例条件，不进入通用规则。
