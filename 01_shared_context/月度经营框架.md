# 月度经营框架

目标：在每月 20 日前，把下一月门店经营的主方向、次方向、责任边界和排期框定下来，并形成一份方案文档和一张推进表。

# 20 日前经营会议

会议至少确认：

- 目标门店和月份。
- 上月真实发生了什么，哪些事项尚未结束。
- 本月最重要的一个主方向。
- 是否存在次方向；没有时明确写“无”。
- 最后拍板人、运营推进人、门店落地人。
- 本月经营板块、关键日期、资源限制。
- 本月明确不做什么。
- 仍需谁在什么时间拍板什么。

缺少原始会议材料、主方向或三类负责人时，只生成缺口清单，不生成正式方案。

# 主方向与次方向

- 主方向是本月所有动作共同服务的核心结果，不是活动名称或渠道清单。
- 次方向只承接必要的第二优先级，不能与主方向争夺相同资源。
- 不根据门店卡或通用方法自行发明主次方向。
- 未确认节点、主题、嘉宾、预算和产品只能进入“待拍板”。
- 门店卡负责说明这家店长期是谁；本月会议负责说明这个月具体怎么打。

# 七段式方案

每家店每个月只生成一份方案文档，固定七段：

1. 本月要做到什么。
2. 谁负责什么。
3. 本月排期。
4. 各板块怎么落地。
5. 本月先不做什么。
6. 还有哪些要拍板。
7. 这套文件怎么用。

文档开头必须包含一句话月度重点、三类负责人和配套推进表入口。文档负责方向和做法，不承担每天更新状态。

# 单表推进

每家店每个月只使用一个 Base 和一张业务表。推进表负责：动作、执行线、状态、归属、承接人、开始与截止日期、交付物/验收、阻塞/待确认、实际情况记录。

动作数量由本月真实经营板块决定，默认控制在 20—30 条。每条动作都要能被具体承接、按日期检查，并留下完成或变化证据。

# 执行过程

月初方案是计划快照，不是假装未来不会变化。执行中遇到新判断、门店反馈、资源变化或外部突发时，在“实际情况记录”和“阻塞/待确认”中写清：原计划、实际发生、变化原因和下一步处理。

# 月末回收

月底复盘至少对照：原计划、实际执行、差异、原因、当时依据，以及下月继续、修正、停止或观察。可复用经验先进入 `05_reviews/月度复盘候选/`，由知识库负责人确认后再更新团队包或内部知识母仓。
