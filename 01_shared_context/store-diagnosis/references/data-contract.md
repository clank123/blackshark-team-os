# 数据与字段契约

## 先取会改变判断的数据

| 资料组 | 要观察什么 | 典型来源及边界 |
| --- | --- | --- |
| 经营结果与经济性 | 收入、交易量、折扣退款、客单结构、成本费用、可得贡献 | POS、结算、财务；订单收入、到账和利润分别定义 |
| 日期、时段和承接 | 星期/餐段、营业时间、桌区、等待、满座或闲置 | 订单与现场；开台表标题不保证每行对应独立到店批次 |
| 产品与组合 | 主动单点、套餐及子项、连带、规格、退菜 | 订单明细及品项；单位不同不混算份额，母子项不重复加总 |
| 购买到兑现 | 下单、支付、核销、撤销、退款及时间差 | 成交/核销/售后；用同批购买队列和合理成熟期比较 |
| 触达与选择前信号 | 曝光、访问、搜索、咨询、内容及疑问 | 平台/作品原文；平台归因不等于增量贡献 |
| 真实消费与放弃 | 来因、替代选择、阻碍、体验、离开原因 | 评价、咨询、现场；保留原话、来源、激励背景及未购买者 |
| 关系与复来 | 可识别顾客的跨次行为、会员/私域/平台状态 | 稳定身份键；跨平台不可直接去重时分别报告 |
| 外卖或其他服务 | 商圈、客单、配送/出餐、取消退款、包装与费用 | 对应渠道明细；堂食表里的打包不代表外卖全量 |
| 供给与外部变化 | 价格菜单、演出、人员、库存、节假日、天气和竞争 | 实际日期和记录；节点机会先作待验证解释 |

正式月度收入结论要有足够完整且可核的月度窗口；利润结论还要相称的成本、费用、退款和结算口径。诊断某个时段或内容疑问，不等完整财务表才开始。

## 每份来源必须记录

门店/平台身份、来源位置、采集时间、业务起止、时间字段含义、筛选、时区、经营阶段、更新频率、实际行数、字段版本、原文件指纹或页面修订、读取覆盖与失败。不要把文件名中的下载时间当交易时期。

每个用于判断的指标留：名称、问题、分子/分母、单位、粒度、去重键、有效状态、时间归属、合并方式、来源定位、缺失/隐藏处理、已知冲突。没有定义的不参与正式比较。

字段清单保留原序号和原名。同名列用“报表+列号+原名”区分；不能转为字典时静默覆盖。未使用的跨行业模板列可以保留在档案，不自动纳入经营结论。新导出与旧版比增删列、类型和语义，确认后再复用脚本。

## 数据可用性检查

1. 原文件只读；区分标题、筛选行、多层表头、合计行和业务记录。XLSX 声明为 A1 等异常范围时，核实际内容，必要时重置维度后读取；不要把单元格范围当实际行数。
2. 检查主键缺失/重复、子表孤儿、重叠导出、退款及零值；总量与来源合计核对。无主键撤单另列，不静默删掉。
3. 缺失、空白、零、负数、隐藏值分开处理；退款可能有合法负值。小样本人群被隐藏不能补零或跨日期填成同一个数。
4. 分清事件日期、营业日、结算日与队列日期；同星期对比、完整日边界、开业/迁址及供给变化要可比。
5. 先核指标语义再选权威来源：店内消费用相应 POS 口径，平台券状态用平台明细，到账用结算，利润用成本费用匹配后的口径。冲突保留差额和影响，不用统一排行榜强行覆盖。
6. 抽查复现：总数、金额、关键状态及关联；失败只阻断依赖该检查的结论，记录原因。

## 常见误读

| 看到了什么 | 不能直接推成什么 |
| --- | --- |
| 自报用餐人数、订单桌号 | 去重客流、稳定家庭人数、真实停留时间 |
| 一人套餐、4升酒、汉堡+酒 | 独自来店、聚会人数、真实动机 |
| 每日去重人数、平台4L快照 | 直接累加为月去重人数、门店全域新老客 |
| 商品销量、点单率 | 不核单位和公式就说偏好或人群份额 |
| 核销、支付、预计收入 | 同一口径的到店、净到手或利润 |
| 评论提及比例 | 全部来客需求比例；带激励评价尤其要单列 |

跨平台仅在有合法、稳定且经验证的键时连接。昵称、相近时间、相同金额都不足以自动认定同一顾客。字段存在也不代表有记录、有权限或可无人值守取得。
