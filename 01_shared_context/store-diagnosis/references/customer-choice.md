# 顾客选择与需求画像

“顾客选择”问的是：这个人在这次处境里想完成什么，在什么替代方案中选择，什么条件让他来、买、留下或放弃。“我们选择服务谁”是下一层经营取舍，两者不要混用。

从证据出发写可用于决策的具体人，不为生动而虚构年龄、职业、收入、常用 App 或家庭结构。有证据且会影响选择时才写。基本背景、当次需求场景和关系阶段可以交叉；同一个人可能今天来吃饭，另一天来聚会。

## 卡片结构

| 信息 | 写法与使用方式 |
| --- | --- |
| 场景名与范围 | 谁在什么情况下，需要完成什么；适用门店/阶段/时间 |
| 触发与同行关系 | 为什么是现在，自己来还是与谁一起；未知就保留未知 |
| 想完成的事 | 功能、情绪、社交需求分别找依据，不机械凑满 |
| 选择与替代 | 不来本店会怎么解决；同行人之间可能有什么冲突 |
| 喜好与厌恶 | 只写会改变选择的条件，区分真实表达和分析推断 |
| 价格与承接条件 | 可核的价格反应、整次消费限制、服务时间、等待和现场条件 |
| 已发生行为 | 购买/核销/到店/使用/复来分别记录，说明证据粒度 |
| 关键主张 | 每条主张独立记来源、支持、反证、把握程度和适用范围 |
| 当前决策用途 | 这张卡使哪项信息、产品、服务或投入选择发生变化 |
| 待验证及回收 | 什么观察能推翻哪一主张，谁能核实，何时复核 |
| 份额 | 单位、分母、期间、归类规则、覆盖、重叠和未知；不能估就写未知 |

画像最少拆四种主张：需求存在、关键约束、解决办法有效、值得投入。某评价支持第一种，不会连带验证后面三种。每张卡不要只用一个“高置信”掩盖差异。

证据按语义编码：本人实际经历、未来意愿/邀约、泛泛适用建议、观察到的行为、分析推断。保留原话出处、发生与采集时间、是否激励、是否去重、覆盖和反面表达。AI角色扮演只生成检查问题，不产生市场证据。

## 份额什么时候能算

先选择单位：订单占比、商品销量占比、收入占比、到店批次占比和独立顾客占比各自不同。分子分母同范围同口径，金额份额不能当人数份额。

场景或需求份额必须有能与实际到店关联的需求证据，以及可解释的归类规则。多场景可多标签但不得强凑100%；选择主场景须说明规则，无法判断者进入未知。样本结果限定在样本和覆盖范围，不自动外推整店。

没有这些条件时可报“含某产品的有效订单比例”等行为结构，并说明它不能证明该需求占比。真实人群理解的精度靠持续反馈提高，不靠给虚构人物补完整履历。
