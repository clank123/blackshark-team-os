# 从数据到经营判断

## 先恢复当前工作

接回同店的资料索引、阶段、画像库及修订、已定目标、现行方案、上次未解问题。已有库的基线与增量一起读；空的修订表不等于原画像被删除。原会议决定是边界与待检验判断，不自动当事实证明。

每次先写一句本次要决定的事，例如“工作日晚餐投入要不要增加”。用户只说看经营时，先用现有数据定位最可能改变选择的问题，不让他重新设计整套指标。

## 七步查看

| 步骤 | 实际查看 | 本步产出 |
| --- | --- | --- |
| 1. 范围与质量 | 同店、窗口、阶段、字段、有效状态、去重、对账及覆盖 | 可用资料和受限结论 |
| 2. 经营结果 | 收入/交易量/客单结构及退款；有条件再看贡献 | 问题发生在哪里，幅度与基线 |
| 3. 结构与解释 | 星期、时段、渠道、产品组合、兑现队列、供给变化 | 哪部分驱动变化，保留有意义的替代解释 |
| 4. 顾客选择 | 原话、行为、未购买/放弃、替代方案、关键条件 | 已观察的选择与未验证的需求解释 |
| 5. 画像与份额边界 | 逐项支持/反证、场景重叠、关系状态及分母 | 该保留或修正的画像，不编份额 |
| 6. 投入取舍 | 适合谁、为何值得、能否兑现、成本产能、其他方向和不追加 | 有边界的推荐，验证/维持/扩大/暂停的理由 |
| 7. 交付与改判 | 关键产出、接收者、使用条件、观察窗口及反证 | 下游可使用的诊断和结果回收要求 |

不强迫每次做完整七步。局部更新沿“新情况→受影响的主张→相关方向是否变化”处理；确有阶段或主要约束变化才重开大范围研究。

## 证据不足怎么推进

把不确定分为四类：需求是否存在、选择障碍是什么、动作是否能改变选择、经济上是否值得。各自补最小的能改判的证据，别用更多曝光去弥补成本未知，或用更多交易去猜未购买者的原因。

缺口写清影响哪项决定、由什么角色核实、何时回来、回来前仍能做什么。只看到了某种组合，就可以检查对应信息是否清楚；不能据此宣布该场景已占整店多少，更不能自动追加预算。

投入判断同时看边际成本、可用产能和挤占：吸引晚间顾客的动作可能影响早时段用餐或其他客人的体验。只比较收入不够。没有成本时可以推进低成本资料核实和已授权制作，扩大付费投入的判断暂留条件。

## 持续更新

记录每源上次完整成功范围与本次结果。重取必要重叠窗口处理迟到退款、评价编辑、订单状态变化，按稳定键与版本比较；同一证据不同导出不重复计新增。

来源返回失败、只能看到当天部分数据、评论只抽查少量作品，分别记录；只有完整取得才推进相应完整覆盖截止。不同来源不共用一个笼统的“已更新到今天”。

已有工具负责采集与保存就复用；本 Skill 负责判断，不虚构后台连接或调度。每周、规划前、重大变化时可触发人工调用；用户明确要求自动运行时再接现有调度并实测成功、失败和恢复。
