# 黑鲨门店运营工作台 Router

## 目标

让成员无需理解仓库结构就能启用、路由和维护工作台；同时保护个人工作区、公共知识与正式发布之间的边界。

## 起手检查

1. 工作台 manifest 存在时，读取根目录的 `workspace-manifest.json`，再读取 manifest 的 `local_map` 值（当前为 `00_workspace/工作台地图.local.md`）并据此解析本地地图；manifest 缺失时不猜来源，直接进入首次启用中的 Router-only 公开 fallback 流程。
2. 查找由 manifest 的 `local_map` 值指向的地图，并核验地图字段与其中路径可用。
3. 地图缺失、路径失效或完整知识包缺失时，进入首次启用流程；地图有效时，只加载当前任务所需上下文，不扫描或重建整个知识库。
4. 不猜测成员的个人写入位置、知识库根目录或飞书发布位置。

完整知识包至少包含工作台根、共享上下文、七店索引、门店卡、模板、两层 Skill 与个人目录契约。

## 首次启用

首次发起黑鲨任务，或成员发送“启用黑鲨门店运营工作台”时，按固定顺序执行：**检测 → 推荐 → 询问 → 配置**。详见 [首次启用](references/first-run.md)。

未经确认，不移动现有仓库、不创建外部目录、不覆盖同名文件。不要在本 Skill 中实现真实下载脚本或飞书操作。

## 任务路由

| 成员意图 | Router 动作 |
|---|---|
| 查询门店 | 读取共享知识、七店索引与目标门店卡；只补充当前问题需要的内容。 |
| 整理经营材料 | 读取或写入个人输入目录，先保留原始材料与待确认项。 |
| 月度经营 | 调用 `$blackshark-monthly-ops-compiler`，由其处理月度经营输入、方案与交付边界。 |
| 调整个人结构 | 更新本地地图；不强迫成员重建整个知识库。 |
| 修改官方知识 | 保留本地差异，标为回流候选，再由公共版本决定是否吸收。 |
| 发布飞书 | 仅在本地交付后，使用操作者指定的位置与自身权限发布。 |

地图字段、路径规则与个人结构调整方式见 [工作台地图契约](references/workspace-map-contract.md)。官方更新与版本冲突处理见 [更新与冲突](references/update-and-conflict.md)。

## 停止条件

仅在以下情形停止并向成员索取必要选择或确认：

- Router-only 公开 fallback 补齐失败或暂存包身份校验失败；
- 发现多个知识库候选但成员尚未选择；
- 工作台地图失效且无法重新匹配；
- 官方基线有未处理本地修改且当前操作要求更新；
- 飞书发布位置或操作者权限不明。
