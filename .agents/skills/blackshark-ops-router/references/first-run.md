# 首次安装与迁移 v0.3

普通经营对话不以安装、地图或迁移为前置。完整包已在当前工作区时，按入口和 manifest 直接处理当前任务；本文件仅在用户要求安装、搬移、补齐或迁移时读取。

## 完整包与位置

在用户给定位置检查现有完整包、manifest 和相关目录。用户已指定来源、位置、创建或迁移范围时继承其授权；否则先说明推荐位置和实际影响，只问缺的选择。不要为回答普通问题扫描整个磁盘、安装工具或移动知识库。

仅有 Router 时，公开来源为 https://github.com/clank123/blackshark-team-os；有 manifest 时核对其来源。下载或复制到唯一暂存目录，检查 workspace 为 blackshark-team-os、版本与声明一致、关键文件齐全。当前为 schema_version 3 / v0.3 试用版；指定发布入口为 https://github.com/clank123/blackshark-team-os/releases/tag/v0.3，不能只查排除预发布的 latest 接口后误报没有新版。schema_version 2 / v0.2 是旧版，可按其实际能力使用或用于迁移，不能称为 v0.3。无法取得指定版本时如实说明，不循环下载。

用户提供 ZIP 时先定位本机可读取文件，检查归档路径没有绝对路径、越界路径或指向外部的符号链接，再解压到新的独立目录，保留 `.agents` 隐藏目录；不解压覆盖已有工作台。核对根目录的 AGENTS.md、manifest、两项 Skill 和模板后，告诉用户应在 Codex 打开哪个完整文件夹；仅在原聊天中读过文件不等于已经切换项目或启用工作台。内部整包已有个人目录及资料时直接核对复用；资料补充包合并到既有工作台时先比对当前记录与来源，保留较新的本地内容。具体用法见根目录团队接入卡。

在已授权的目标有同名内容时先核对差异；不覆盖个人目录、地图、现有项目和手工修改。无冲突且内容核验通过后再启用新包。内容或身份核验失败保持原位置不变，只处理本次暂存目录。

有有效地图沿用；用户要求在当前工作区生成文件且无地图时使用 manifest 默认个人目录并说明位置。需要跨目录配置时才生成地图。验收能定位根目录、方法、目标门店资料、两个 Skill、个人目录；飞书默认目标为空并不妨碍本地工作。

## v0.1 兼容迁移

需要迁移且发现 `03_projects/` 或旧复盘目录 `05_reviews/月度复盘候选/` 有真实内容，Router 必须先展示迁移计划，而不是直接处理。项目迁移只排除根脚手架文件 `03_projects/README.md`，复盘迁移只排除根脚手架文件 `05_reviews/月度复盘候选/README.md`；任何项目内部或嵌套 `README.md` 一律视为用户真实内容，纳入清单、复制和验收。未经确认不复制、移动、重命名、删除；确认后默认复制，并保留源文件。旧副本默认不删除；未经迁移后第二次明确确认不删除。

### 预检迁移清单

预检逐文件生成迁移清单，列出来源、目标、源相对路径、映射后目标相对路径、文件数量、字节数、SHA-256、目录映射、映射结果和同名冲突。旧项目目标为 `03_my_workspace/01_projects/YYYY-MM-门店名称/`，且五条映射必须精确：`00-input/` → `00_input/`、`01-context/` → `01_context/`、`02-drafts/` → `02_drafts/`、`03-feishu-payload/` → `02_drafts/legacy-feishu-payload/`、`04-verification/` → `03_verification/`。未知内容放入目标项目 `legacy-v0.1-unmapped/`，未知内容保持相对结构，不丢弃。

预检先检测两个源映射到同一最终相对文件路径的迁移内碰撞，也检测既有目标同名/同路径；任何碰撞先停止，展示差异让用户决定，不合并猜测。父子目录本身不视为同一路径重复，真正碰撞按最终相对文件路径判断。同名目标或目标已有内容时停止自动迁移，展示差异让用户决定。必须明确预检 `02-drafts/legacy-feishu-payload` 与 `03-feishu-payload` 等可能映射到同一路径的碰撞。旧复盘由成员逐项选择写入个人 `03_my_workspace/03_reviews/` 或团队候选 `05_upstream_candidates/`；归属不确定时必须让用户选择，不猜。

### 复制、验收、收据与清理

确认后，在最终目标的同级目录建立本次唯一暂存目录，先全部复制到暂存，不直接写最终目标。用相对路径+字节数+SHA-256 逐文件核验载荷；任一失败只清理本次唯一暂存目录，源文件与既有最终目标保持原样。全部载荷核验后，先生成并核验迁移收据.md（在本次唯一暂存目录内）。收据记录并引用载荷文件清单的 SHA-256，以及源清单摘要、目标、映射、文件数、哈希验收和完成时间；载荷哈希明确排除收据自身，避免自引用。收据生成或核验失败仍只清理本次唯一暂存目录，源文件与既有最终目标保持原样。仅当载荷与收据均核验成功，再将包含收据的暂存目录一次性同级重命名为最终目标。

最终目标验收时确认迁移收据.md 存在，并重新计算除收据外载荷清单哈希，确认与收据一致。二次运行先读最终目标内收据：源未变+目标哈希一致→跳过，报告已完成。源或目标变化、收据不一致时停止并展示差异，不重复复制/合并。验收新位置后，再次询问是否移动/清理旧副本；清理前重新核对收据与目标哈希，失败不清理源。迁移失败也保持旧内容原样，不自动删除。
