# 更新与冲突

工作台变更分为三类归属：

- **官方基线**：公共仓库维护的共享知识、门店卡、模板与 Skill。
- **个人扩展**：成员个人目录、个人地图指向的路径，以及只供本人使用的结构或材料。
- **回流候选**：有团队复用价值、等待知识库负责人审查并决定是否进入官方基线的修改。

更新时**不静默覆盖**任何本地内容。使用以下固定矩阵：

| 当前状态 | Router 动作 |
|---|---|
| 只有个人目录变化 | 正常更新官方基线 |
| 官方基线有本地修改 | 暂停自动更新并展示差异 |
| 修改只需本人使用 | 展示差异并提出复制/迁移建议；确认目标路径与同名冲突，得到明确确认后默认复制到个人扩展并保留源文件 |
| 修改值得团队复用 | 写入回流候选，等待公共版本吸收 |
| 路径被调整 | 读取地图；地图失效则重新匹配 |

对于只需本人使用的官方基线改动，不能直接移入个人扩展。先展示差异，提出复制/迁移建议，并确认目标路径与同名冲突；只有成员明确确认后才执行。默认采用复制并保留源文件，除非成员另行确认迁移方式。

公共更新不得覆盖 personal/local map。没有 GitHub 账号的同事仍只消费公共版本，不要求推送。回流候选由知识库负责人决定是否吸收；未吸收前继续保留为个人扩展或候选记录。

`blackshark-monthly-ops-compiler` 只处理月度经营编译与其交付边界；版本更新和个人/公共知识冲突由 Router 在进入编译器前处理。
