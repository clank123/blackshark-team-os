# 黑鲨月度经营编译器 v0.3

工作区根从本 Skill 向上定位。读根目录 manifest、`01_shared_context/月度经营框架.md`、`01_shared_context/门店资料使用与更新.md`，以及 [输入约定](references/input-contract.md)。只读目标门店及当期有关材料。

## 1. 接住已有方向与工作

提取本店／月份、来源、已定方向、原来不做、资源边界及已有方案／推进表。用户给出的明确补充同样是输入，不强制必须有完整会议文件。缺店名或时间且无法推断时只问对应问题。

若已给明确整体方向，直接整理本店怎样承接；若方向尚模糊，先提出有依据的候选判断与取舍，让运营回应。候选保持建议身份，不能伪装负责人已决定。缺负责人、预算或日期仍先完成工作稿，将缺口挂在受影响项上；不退回整批材料。

## 2. 带着逐项形成安排

沿方法按需推进：本店本月主攻及顾客行为 → 主项目 → 选择产品／页面／现场／内容／推广等手段 → 依赖与资源 → 倒排时间 → 品牌节点、次线与日常维护 → 分工与结果回收。

从已有材料预填，逐次呈现当前形成的内容。不要让运营先交一套完整策略作业。服务板块用于选取和查漏，不能机械全部派发。必要动作全部保留，展示可按当前重点折叠。

每个主项目说明目的和边界，子任务能独立交付、验收并有主要承接人。支持运营提出实质异议；已定方向只有相关前提变化时才重看。跨店资源只写实际需要的依赖，不复制其他店整套任务。

## 3. 固定版本的两个成果

读 [输出约定](references/output-contract.md)，沿根目录当前版本的方案模板与表结构生成：

- 七段式方案；第四段按主项目组织做法，第七段放推进表。
- 一张推进表；主项目可展开子任务，六状态、五个默认视图。任务编号保持稳定，父任务是关系，不靠文字缩进冒充。

AI 同时维护机器记录、CSV 与核验状态，留在项目内部；对运营主要呈现方案与推进表。`scripts/compile_monthly.py` 负责验证记录关系并生成本地树形预览和表格，具体调用见输出约定。它不执行飞书写入，也不证明经营效果。

草稿允许局部待定。标记为“待定”的责任或日期，不得在正式执行时伪造填齐。正式下发前检查可执行子任务的责任、日期和验收；需要拍板的项目可以保留，但应清楚区分与已可执行任务。

## 4. 发布、变化与下轮

用户要飞书成果时，读 [发布与验收](references/publish-and-verify.md)，继承已有授权，完成 Base 数据、父子展开、文档正文与真实内嵌视图。只有链接不能交差为内嵌；只有父关系字段不能证明树形已配置。工具不足时完成其余部分，准确指出缺少哪项，不提前宣称成功。

同店同月优先修改原方案与表，记录实际变化和理由；已完成、取消的任务不因新生成自动重置。关键经营取舍变化回方案，任务状态回表。周期结束把事实接回本地门店记录，方法候选保留条件。模板与 Skill 版本各自登记，发布新模板不自动迁移全部旧表。
