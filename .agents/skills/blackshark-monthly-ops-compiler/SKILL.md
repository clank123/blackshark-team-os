# 黑鲨月度经营编译器

## 目标与边界

把已确认的月度经营判断转成一份七段式文档，以及一个 Base 中的一张业务表。Base 固定使用十个固定字段、六个状态和五个固定视图。

- 不替团队发明主方向、次方向或负责人。
- 不自动创建仪表盘。
- 不自动创建Workflow。
- 不自动创建多表经营控制台。
- 不为凑数量制造动作。

## 1. 路由上下文

1. 从用户输入识别目标门店和目标月份。
2. 读取 `01_shared_context/` 中的三份共享上下文。
3. 读取 `02_store_cards/00-七店索引.md`。
4. 只读取目标门店卡，不加载其他六店的详细卡。
5. 读取目标项目 `03_projects/YYYY-MM-门店名称/00-input/` 内的月度会议材料与明确补充。
6. 读取 [输入合同](references/input-contract.md)，按其中的真值优先级处理冲突。

## 2. 执行输入 Gate

检查以下必填项：目标门店、目标月份、原始月度会议材料、主方向、次方向状态，以及最后拍板人、运营推进人、门店落地人。

- 次方向可以是“无”，但不能处于未知状态。
- 任何必填项不足时，只输出缺口清单，不生成正式方案，也不创建发布产物。
- 当前状态缺少有效证据时明确标记“待门店确认”。
- 不猜测日期、数据、负责人或拍板结论。

## 3. 编译本月方案

1. 区分四类内容：会议事实、已确认方向、待拍板、本月不做。
2. 允许本月已确认事实覆盖门店卡中过期的当前状态；不得静默覆盖长期基因。
3. 长期基因与本月事实冲突时，将证据列入复盘候选。
4. 按 `04_templates/月度运营方案模板.md` 生成七段式正文。
5. 按 `04_templates/运营推进表模板/schema.json` 生成动作；每行至少有动作、执行线、状态、归属、验收、日期和承接人。
6. 读取 [输出合同](references/output-contract.md)，校验标题、字段、状态、视图和动作数量边界。

## 4. 生成发布前预览

在任何外部写入前，展示一次完整的发布前预览，至少包括：

- 一句话月度重点和三类负责人。
- 七段式草稿。
- 按执行线分组的任务清单。
- 十个固定字段、六个状态、五个固定视图。
- 仍存在的缺口、待拍板和待门店确认事项。
- 预计创建或更新的目标位置、文档完整标题和 Base 完整标题。

预览阶段不执行外部写入。

## 5. 确认并发布

只有获得操作者明确确认本次预览后，才可以向操作者指定的黑鲨知识库位置写入。执行发布前读取 [发布与验收合同](references/publish-and-verify.md)。

1. 按完整标题搜索已有文档和 Base。
2. 有匹配产物时优先更新或复用；不重复创建同名 Base。
3. 先创建或复用 Base 与一张业务表，再创建或更新文档。
4. 将 Base 的实际入口写回文档头部“配套推进表入口”。
5. 不扩大操作者确认过的内容和权限范围。

## 6. 回读验收

发布后必须：

1. 回读文档，检查完整标题、七段式内容和配套推进表入口。
2. 回读 Base，检查只有本月需要的一张业务表。
3. 回读字段、状态、视图和记录，核对数量与关键值。
4. 把验收结果写入本月项目目录。

只有全部回读通过，才能报告“已发布并验证”。若回读失败或只能确认部分结果，必须指出未验证项，不得声称交付已验证。

## 7. 失败与幂等

- 创建前按完整标题查重，重试时复用已创建的产物。
- Base 已成功、文档失败时，继续复用原 Base，不新建第二份。
- 文档已成功、记录不完整时，只修复缺失记录，不重复建文档。
- 无法确认现有产物身份时停止写入，列出候选项请操作者决定。
- 所有未确认事项保持“待拍板”或“待门店确认”，不得悄悄改成已决定。
