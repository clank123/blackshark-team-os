# 输出合同

## 文档头部

- 一句话月度重点。
- 最后拍板人。
- 运营推进人。
- 门店落地人。
- 配套推进表入口。

正文说明必须表达：文档负责方向与做法，推进表负责动作、承接人、日期、状态、验收和卡点。

## 七段式标题

一级标题严格依次为：

1. `1. 本月要做到什么`
2. `2. 谁负责什么`
3. `3. 本月排期`
4. `4. 各板块怎么落地`
5. `5. 本月先不做什么`
6. `6. 还有哪些要拍板`
7. `7. 这套文件怎么用`

不要增加第八段，也不要把推进表明细整段复制到文档正文。

## Base 结构

一个 Base 只保留一张名为“本月推进表”的业务表。

十个字段按此顺序创建：

1. 动作：文本，主字段。
2. 执行线：单选，选项跟随当月方案。
3. 状态：单选。
4. 归属：单选，至少包含“黑鲨”和目标门店。
5. 交付物/验收：文本。
6. 实际情况记录：文本。
7. 截止日期：日期。
8. 开始日期：日期。
9. 承接人：人员。
10. 阻塞/待确认：文本。

六个状态固定为：未开始、进行中、已完成、阻塞、待拍板、取消。

五个视图固定为：

1. 全部推进：按截止日期升序。
2. 本月排期：开始日期到截止日期的时间视图。
3. 按承接人：按承接人分组，组内按截止日期升序。
4. 待拍板与阻塞：只显示这两种状态。
5. 门店要做：只显示目标门店归属且未完成、未取消的动作。

## 动作最小合同

每条动作必须至少能回答：

- 做什么。
- 属于哪条执行线。
- 由黑鲨还是门店承担。
- 唯一主承接人是谁。
- 何时开始、何时完成。
- 用什么交付物或结果验收。
- 当前是什么状态。

常规月份默认控制在 20—30 条，但这只是复杂度边界，不是凑数目标。无法独立验收的细碎步骤应合并；真实经营需要超过范围时，在预览中说明原因后由操作者决定。
