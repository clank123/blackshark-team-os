# 发布与验收合同

## 发布前

1. 以只读方式定位操作者指定的黑鲨知识库节点，并展示节点名称与路径。
2. 生成文档与 Base 的完整标题，建议统一使用“目标月份 + 门店 + 月度运营方案/运营推进表”。
3. 按完整标题搜索目标节点，列出现有同名或近似产物。
4. 展示发布前预览：方向、负责人、七段式草稿、动作清单、表结构、缺口和目标位置。
5. 获得操作者对本次预览、目标位置和新建/更新方式的明确确认。

没有明确确认时保持只读，不创建、不更新、不移动任何外部内容。

## 发布顺序

1. 复用已确认的同名 Base；没有匹配项时创建一个 Base。
2. 在 Base 中创建或修正“本月推进表”，确保十字段、六状态、五视图符合合同。
3. 按预览写入动作记录，保存实际记录数。
4. 复用已确认的同名文档；没有匹配项时创建文档。
5. 写入七段式正文，并把 Base 的实际入口写入“配套推进表入口”。
6. 将文档与 Base 放在操作者确认的知识库位置，不自行改变空间成员或权限。

部分失败时复用已经成功创建的产物，只补失败部分；不得通过重复新建来掩盖错误。

## 回读验收

发布后重新读取真实产物，不使用提交前草稿代替回读：

1. 回读文档标题、七个一级标题、三类负责人和配套推进表入口。
2. 回读 Base 标题和业务表数量，确认只包含本月需要的一张业务表。
3. 回读十个字段的名称、类型与顺序。
4. 回读状态选项和五个视图名称、筛选或分组规则。
5. 回读记录数，并抽查每条记录的动作、归属、承接人、日期、状态和验收。
6. 把文档入口、Base 入口、记录数、通过项、未通过项和验收时间保存到 `03-verification/`。

只有全部关键项通过时才报告“已发布并验证”。任何回读失败、权限不足或结构不一致都要列为未验证，并说明下一步修复动作。
