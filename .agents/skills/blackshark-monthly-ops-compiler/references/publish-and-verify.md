# 发布和验收 v0.3

沿用户本次目标与权限执行。只请求草稿时不写飞书；明确要求把具体版本写到具体位置时继承授权，先做可审阅结果，不重复要求批准未变化的内容。位置不明、同名对象有歧义或权限不足，只停止相关外部动作。

## 工具条件与预览

使用当前可用的飞书文档和 Base 工具；先读相应工具说明，不将本包 schema 当 API 请求。只读核对已有目标、表、字段和视图，记录当前 ID。按完整标题及项目身份查重。现有模板结构优先复用，保留额外字段与已有数据，不自动重建。

预览给出方向、主项目及子任务、责任、时间、待定项和目标；已确认的范围可连续执行。没有飞书能力时完成本地方案和树形数据，清楚注明尚未产生真实飞书成果。

## 真实表与层级

1. 创建或复用目标 Base 的业务表，按模板版本映射原十字段、任务编号、父任务。先读真实字段类型；人员映射使用实际身份，不能把姓名字符串冒充人员 ID。
2. 先建或更新主项目，保存任务编号到真实记录 ID；再分层建子任务及父关联。关系值使用返回的真实 ID，不能直接写本地 P1／T1 当飞书 ID。
3. 配置当前平台支持的原生父子记录展开／子任务显示，关联正确的表和关系。自关联字段不自动等于原生树形；只按执行线分组也不等于项目下展开。
4. 维护全部推进、本月排期、按承接人、待拍板与阻塞、门店要做五个默认视图，具体筛选保留现有约定。不同角色查看必要列；不为展示限制删掉必要任务。
5. 按稳定编号复用记录；重试先读服务端结果，未知创建是否成功时先核验，避免重复。老表匹配歧义只阻塞受影响记录。

若当前 API 无法设置原生层级，先检查官方工具能力；用户允许界面操作且工具可用时可完成配置。否则留下明确操作点，已有数据保留，并报告“父关系已写，原生展开未验证”。不要用文本缩进或链接替代后宣称已完成。

## 真实方案内嵌

创建或更新七段式正文，在第七段插入目标 Base 的实际视图块／官方支持的嵌入组件，顶部可同时保留备用链接。使用实际 Base、table、view 标识；检查读者能在文档中看到该视图。普通链接、链接卡片、截图和静态 Markdown 表都不算内嵌可操作视图。

当前接口无法创建内嵌时，查工具或官方接口能力；可在获授权界面操作中完成，否则明确剩余操作。不要把工具不支持写成已经内嵌。权限只沿当前授权处理，不默认扩大到全员或互联网。

## 四项验收

分别记录在项目 `03_verification/发布回执.json`：

- document：实际文档标题、七段式内容、版本、人员及入口。
- base_data：字段、状态、视图及完整记录／关系与本地预览一致。
- hierarchy：至少核对主项目展开后对应子任务及归属；保存工具回读或界面检查依据。
- embedded_view：实际文档内嵌块指向正确表与视图且可见；保存块标识或界面检查依据。

每项状态为 `未执行 / 通过 / 未验证 / 失败`，附资源标识及检查依据。只有四项实际通过才称“方案与嵌套推进表已发布并验证”。本地脚本不能自行把这些状态置为通过。

部分完成时列出已完成资源与剩余动作，续跑复用原对象。不通过重建整套文档和表掩盖失败；不自动发群、建群、派任务或开启自动化。
